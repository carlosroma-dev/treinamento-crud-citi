1 · Conceitos básicos

O que é uma API?

Pense num restaurante. Você não entra na cozinha: faz o pedido ao garçom, que leva até a cozinha e volta com o prato.

Clientesite, app, Thunder Client
⇄
APIo garçom: o nosso código
⇄
Banco de dadosa cozinha: PostgreSQL

A API recebe o pedido (a requisição), confere se faz sentido, busca ou grava no banco e devolve uma resposta. O cliente nunca fala direto com o banco.

CRUD

LetraOperaçãoMétodo HTTPFunção do Prisma
CCreate (criar)POSTcreate
RRead (ler)GETfindMany, findUnique
UUpdate (atualizar)PATCHupdate
DDelete (deletar)DELETEdelete
📘 PATCH ou PUT?O PUT substitui o recurso inteiro. O PATCH altera só o que você mandar. Aqui usamos PATCH: se o corpo tiver só { "preco": 9990 }, só o preço muda.

Anatomia de uma requisição

PATCH  http://localhost:3001/plantas/3?avisar=true
Content-Type: application/json

{ "preco": 9990 }
OndeNo exemploComo ler no ExpressPara que serve
Params (parte da rota)3req.params.idIdentificar o recurso
Query string (depois do ?)avisar=truereq.query.avisarOpções e filtros
Body (corpo){ "preco": 9990 }req.body.precoOs dados a criar ou mudar
⚠ Params e query string são sempre textoEm /plantas/3, req.params.id é a string "3". Em ?petFriendly=true, o valor é a string "true". Você vai precisar converter. Já o body, por ser JSON, mantém os tipos.

Status HTTP

StatusQuando usarExemplo no desafio
200 OKDeu certo e há algo para devolverListar, buscar, editar, vender
201 CreatedAlgo novo foi criadoCadastrar planta
204 No ContentDeu certo e não há corpoDeletar planta
400 Bad RequestO cliente mandou dados faltando ou inválidosPreço negativo, venda sem estoque
404 Not FoundO recurso pedido não existeBuscar a planta 999
500 Internal Server ErrorAlgo inesperado quebrou do nosso ladoO banco caiu
💡 Regra de bolso2xx: deu certo. 4xx: a culpa é de quem pediu. 5xx: a culpa é nossa. Por isso o catch genérico responde 500, nunca 400.

JSON e tipos

{
  "nome": "Jiboia",          // string: entre aspas duplas
  "preco": 3490,             // número: SEM aspas
  "petFriendly": false,      // booleano: SEM aspas
  "luminosidade": "SOMBRA"   // enum: chega como string
}

"preco": "3490" é texto, não número, e uma API bem validada recusa com 400. JSON não aceita comentários: os // acima são só explicação.

async/await e try/catch

Falar com o banco leva tempo, então o Prisma devolve uma Promise. O await espera o resultado e só pode ser usado dentro de uma função async. O try/catch garante que, se algo der errado, a API responde 500 em vez de deixar o cliente esperando.

export const readAllUsers = async (req: Request, res: Response) => {
  try {
    const users = await UserRepository.findAllUsers(); // espera o banco responder
    return res.status(200).json(users);
  } catch (error) {
    console.error(error);                              // mostra o erro no terminal
    return res.status(500).json({ message: "Erro ao buscar usuários." });
  }
};

Lendo o CRUD de usuário

O model, em prisma/schema.prisma: cada model vira uma tabela, e cada linha, uma coluna.

model User {
  id        Int      @id @default(autoincrement())  // chave primária: 1, 2, 3...
  nome      String
  conta     Conta                                   // enum: CPF ou CNPJ
  documento String   @unique                        // não pode repetir
  createdAt DateTime @default(now())                // preenchido na criação
  updatedAt DateTime @updatedAt                     // atualizado a cada edição
}

As rotas, em src/routes.ts: a URL é o recurso no plural, e o que muda é o método.

routes.post("/users", UserController.createUser);
routes.get("/users", UserController.readAllUsers);
routes.get("/users/:id", UserController.readUserById);
routes.patch("/users/:id", UserController.updateUser);
routes.delete("/users/:id", UserController.deleteUser);

O repository: funções pequenas, uma consulta cada. Prisma.UserCreateInput é um tipo gerado a partir do model, e o TypeScript avisa se faltar campo ou o tipo estiver errado.

export const findUserById = async (id: number) => {
  return await prisma.user.findUnique({
    where: { id: id },
  });
};

O controller: quase todo handler segue ler → validar → chamar o repository → responder. Cada problema tem seu return com um status, e o caminho feliz fica no final.

export const createUser = async (req: Request, res: Response) => {
  try {
    const { nome, conta, documento } = req.body;           // ① lê

    if (!nome || !conta || !documento) {                   // ② valida
      return res.status(400).json({ message: "Preencha nome, conta e documento." });
    }

    const user = await UserRepository.createUser({         // ③ grava
      nome: nome, conta: conta, documento: documento,
    });

    return res.status(201).json(user);                     // ④ responde
  } catch (error) {
    console.error(error);
    return res.status(500).json({ message: "Erro ao criar usuário." });
  }
};
💡 Experimente antes de codarChame todas as rotas de /users no Thunder Client, incluindo os erros: um id que não existe, um corpo vazio, um cadastro sem a conta. Ver as respostas ajuda muito a entender o código.

Os campos, as rotas e as regras estão no DESAFIO.md. Siga a ordem abaixo e faça um commit ao fim de cada passo.

PASSO 1O model e o enum

Em prisma/schema.prisma, crie o enum Luminosidade e o model Planta. A sintaxe, com outro tema:

enum Tamanho {
  PEQUENO
  MEDIO

model Camiseta {

  • Os nomes dos campos estão exatamente como no enunciado (regaACadaDias, com as maiúsculas no lugar)?
  • preco é Int, e não Float? Em centavos, as contas com dinheiro são exatas (em JavaScript, 0.1 + 0.2 dá 0.30000000000000004).
  • Tem createdAt e updatedAt, como no User?

PASSO 2A migration

A migration é um arquivo SQL em prisma/migrations/ que descreve a mudança no banco. Ela também atualiza os tipos do Prisma Client: depois dela, prisma.planta aparece no autocompletar. Confira com yarn studio.

PASSO 4O controller: validações

Crie src/controllers/PlantaController.ts. É o passo com mais detalhes.

Convertendo e validando o id. Se repetir em várias funções, vale criar uma função auxiliar no topo do arquivo.

const id = Number(req.params.id);     // "3" vira 3; "abc" vira NaN
if (!Number.isInteger(id) || id <= 0) {
  return res.status(400).json({ message: "O id precisa ser um número inteiro positivo." });
}
⚠ A armadilha mais importante: !campo No UserController, !nome || !conta funciona porque todos os campos são textos. Nas plantas, quebra:
Valor recebido!valorÉ válido na planta?
undefined (não enviado)true❌ Precisa recusar
0 (estoque zero)true✅ Planta esgotada é válida
false (petFriendly)true✅ Planta tóxica para pets é válida
Para saber se um campo foi enviado, compare com undefined: if (estoque === undefined).

Validando tipos e regras. Depois de garantir que o campo veio, confira o tipo e o valor:

Para validar…Use
Texto não vaziotypeof nome === "string" && nome.trim() !== ""
Inteiro (recusa "8990", 89.9 e NaN)Number.isInteger(preco)
Booleanotypeof petFriendly === "boolean"
Valor do enumObject.values(Luminosidade).includes(luminosidade), com import { Luminosidade } from "@prisma/client"

Combinando com as regras: !Number.isInteger(preco) || preco <= 0 significa "preço inválido". Escreva uma checagem para cada regra, cada uma com uma mensagem clara.

POST x PATCH. No cadastro, todos os campos são obrigatórios; na edição, nenhum é, mas os que vierem passam pelas mesmas regras. Uma função que valida só os campos enviados (pulando os undefined) serve para os dois. No POST, antes dela, confira se nenhum campo está faltando.

404 antes de editar ou deletar. Busque a planta primeiro e responda 404 se não existir. Sem isso, o erro do Prisma cai no catch e vira um 500 errado.

Não passe req.body direto para o banco. O cliente poderia mandar campos que você não espera, como id ou createdAt.

// ✅ você escolhe exatamente o que vai para o banco
const { nome, especie, preco, estoque, luminosidade, petFriendly, regaACadaDias } = req.body;
await PlantaRepository.createPlanta({ nome, especie, preco, estoque, luminosidade, petFriendly, regaACadaDias });

PASSO 5As rotas

Importe o controller e registre as rotas em src/routes.ts. O Express usa a primeira rota que combinar, então rotas fixas vêm antes das que têm parâmetro:

routes.get("/plantas/esgotadas", PlantaController.readPlantasEsgotadas);  // ✅ antes
routes.get("/plantas/:id", PlantaController.readPlantaById);

Na ordem inversa, GET /plantas/esgotadas chama readPlantaById com id = "esgotadas".

PASSO 6Filtros na listagem

GET /plantas?luminosidade=SOMBRA&petFriendly=true chega em req.query. Filtro não enviado é undefined, e no where do Prisma condições undefined são ignoradas: uma única consulta resolve todas as combinações.

// exemplo com usuários: se nome for undefined, lista todo mundo
prisma.user.findMany({
  where: { nome: nome },
});
  • Converta o booleano: petFriendly === "true", sem transformar um filtro não enviado em false.
  • Valide: ?luminosidade=LUA ou ?petFriendly=talvez retornam 400.
  • Filtro sem resultado não é erro: é 200 com [], não 404.
💡 Para os bônusPesquise na documentação do Prisma por contains com mode: "insensitive" (busca) e por orderBy (ordenação).

PASSO 7A venda

  1. Valide o id → 400.
  2. Valide a quantidade: inteiro maior que zero → 400.
  3. Busque a planta → 404.
  4. Confira planta.estoque >= quantidade → senão 400, sem alterar nada. Para mensagens com variáveis, use crase: `Temos só ${planta.estoque} vasos`.
  5. Diminua o estoque. O Prisma faz a conta: data: { estoque: { decrement: quantidade } }.
  6. Responda 200 com a planta atualizada.
📘 Para pensar (não é obrigatório)E se duas pessoas comprarem o último vaso ao mesmo tempo? As duas podem passar pelo item 4 antes de qualquer uma chegar ao 5. Pesquise sobre updateMany com condição no where. Se resolver, conte no documento da API.

PASSO 8O valor total do estoque

Para cada planta, preco × estoque; depois, some tudo.

Plantaprecoestoquepreco × estoque
Jiboia34901034900
Calathea7990215980
Total12 vasos50880 (R$ 508,80)

O aggregate do Prisma soma uma coluna, mas não uma multiplicação de colunas. Busque as plantas (só preco e estoque, com select) e some no código, com for ou reduce. Com a loja vazia, a resposta é 200 com os valores zerados.

6 · Antes de entregar

Os entregáveis e os critérios de avaliação estão no DESAFIO.md. Confira:

  • O projeto sobe do zero com docker compose up -d --build e yarn migration
  • A migration da Planta está commitada em prisma/migrations
  • Todos os testes da parte 4 passam
  • Os nomes de campos e rotas estão exatamente como no enunciado
  • yarn typecheck termina sem erros
  • Não há console.log de teste, imports sem uso ou código comentado (o console.error do catch pode ficar)
  • O .env não foi commitado
  • O documento da API está completo e bate com o que a API faz

Travou? Como pedir ajuda

Pedir ajuda não tira ponto. Antes, tente uns 20 minutos: leia o erro com calma, veja os logs (docker compose logs -f server), compare com o CRUD de usuário e releia a parte 5. Ao pedir ajuda, mande o que queria que acontecesse, o que aconteceu (erro completo ou print), o que já tentou e o trecho de código.

Documentações: prisma.io/docs, expressjs.com/pt-br e developer.mozilla.org (status HTTP).

TermoSignificado
